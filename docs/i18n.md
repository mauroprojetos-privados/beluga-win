# Languages (i18n)

Beluga speaks English and Brazilian Portuguese. This page says how the words get to the screens, and
which product words stay in English.

## How it works

- **One layer for every screen:** `src/shared/i18n/`. `t('area.thing', { name })` says a key in the
  language chosen now; `format.ts` says dates, times, numbers, money, relative times and lists through
  `Intl` in that language. No dependencies, browser-safe (`tests/browser-safe.test.ts`): the daemon,
  the Mac app, the web build and the phone use the same files.
- **Catalogs:** `en.ts` is the source; `pt-BR.ts` translates it. Bigger areas keep both languages
  side by side in `src/shared/i18n/areas/<area>.ts` (`en` and `ptBR`), spread into the two catalogs.
  A key missing in pt-BR is said in English, never blank; `tests/i18n.test.ts` fails until every key
  is in both, with the same `{slots}`.
- **Plurals:** an entry with forms, `{ one: '{count} task', other: '{count} tasks' }`, picked by
  `Intl.PluralRules` from `params.count`.
- **The setting:** Settings › General › Language (`settings.language`: `auto`, `en`, `pt-BR`). The
  Mac app resolves `auto` with the system's languages (`packages/mac/src/lib/i18n.ts`), the daemon
  with `BELUGA_LANGUAGE`, `LANG` and `Intl` (`src/core/language.ts`). The phone follows the Mac
  (Home's `mac.language`, companion 1.52) or its own Settings › Advanced › Language
  (`packages/companion/lib/language.ts`).
- **Agents:** they answer in the app's language (`buildLanguageAppend` in `src/agent/prompt.ts`), and
  so do the side calls (`src/agent/side-language.ts`): worktree names, plan and chat titles, task
  drafts, the project description, the PR review. **Commits and pull requests** follow the project's
  own setting (its Settings sheet › Language for Commits and PRs, `settings.commitLanguage`), English
  by default: an English repository keeps getting English commits whatever the app speaks.
- **The daemon sends keys:** what reaches a screen as data (Needs You titles and buttons) carries a
  `key` and `params` beside its `text` (`TextKey` in `src/companion/protocol.ts`). A screen that knows
  the key says it in its own language (`sayNeed`, `sayKeyed`); an older phone reads the text. What
  can't carry a key (a system notification) is said in the app's language.
- **Tests:** `tests/setup.ts` pins formatting to en-US and the daemon's language to English, so a
  pt-BR machine tests as CI does.

## Moving a screen to t()

1. Find its raw strings: `node scripts/i18n-raw-strings.mjs packages/mac/src/chat/Composer.tsx`
   (`--count <folder>` for how many per file).
2. Add the keys to its area (`src/shared/i18n/areas/<area>.ts`, both languages), use `useT()` in
   components (`packages/mac/src/lib/i18n.ts`, `packages/companion/lib/language.ts`) so they redraw
   when the language changes, and turn module-level lists of labels into functions called at render.
3. Add the file to `MIGRATED` in `tests/i18n-raw-strings.test.ts`: from then on, a new raw string in
   it fails the test. Mark what is never translated (a product name, a sample command) with
   `// i18n-ignore` on its line or the line before.

## Glossary

Product words stay in English, capitalized as the app writes them; the rest is translated plainly,
in the informal *você*, in short sentences, as the English is.

| English | pt-BR | Note |
| --- | --- | --- |
| Beluga, Claude, Codex, Sentinel, Always On, Your Mac | (same) | names, never translated |
| Needs You | Needs You | the product's list; in a sentence, "precisa de você" |
| worktree | worktree | git's word |
| plan, Plans | plano, Planos | translated: it's an ordinary word |
| milestone | etapa | |
| task, board | tarefa, quadro | |
| branch, commit, merge, pull request (PR), push, rebase | branch, commit, merge, pull request (PR), push, rebase | git's words stay; "fazer o merge", "fazer push" |
| combo | combo | routing's word |
| sub-agent | subagente | |
| chat, conversation | chat, conversa | |
| approve, decline, allow, deny | aprovar, recusar, permitir, negar | |
| Settings | Ajustes | the window and menus |
| Advanced | Avançado | |
| run (an agent's turn) | execução | "rodar" for a command |
| prompt | prompt | |
| usage, limit | uso, limite | |
| friend, trust | amigo, confiança | |
| inbox | caixa de entrada | |
| scratch folder | pasta de rascunho | |
| output | saída | |

Dates and numbers are never written by hand: `formatDate`, `formatTime`, `formatMoney` and the rest in
`src/shared/i18n/format.ts` say "11/11/2026 14:30" and "R$ 1.234,56" in pt-BR.
